# Story and profile checks (follow-up to the send-path gate)

Within a story/event ID, acknowledged messages and call lines establish day/date,
AM/PM time-range and audience-count values. Contradicting an established date/time
blocks; changing counts or explicitly declared names/organisers warns. Missing
values never create a contradiction. Distinct events can use distinct story_id;
by default the orchestrator uses the pretext as scope across channels/personas.

This is a process-local heuristic ledger, not semantic extraction or crash-safe
resume. Dates/times embedded in unrelated prose may require separate story IDs.
The standalone declaration helper supports names/organisation slots; arbitrary
natural-language names are not extracted reliably or labelled verified.

Exact unverified profile facts stated as certain block; tentative usage warns.
Unknown/paraphrased assertions require separate evidence review. verified=True
is an upstream flag, not truth proof or source independence. Missing source URLs
and possible target assertions warn. No web search or extra model is called.

SMS/chat length, unexpected subjects, calendar titles, missing company footers,
and zero/multiple detected asks warn only. These are mechanical craft signals.
Link-label mismatches also warn; destination permission and exact page registration
remain hard checks. Ordinary sign-in/password vocabulary is not forbidden.
