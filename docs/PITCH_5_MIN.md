# Five-minute rubric version

Use only if organisers confirm five minutes of speaking time. The earlier event
guide says three minutes plus Q&A; keep PITCH_3_MIN.md ready. No spoken timing
has been certified here.

## 0:00-0:35 - Problem and scope

Use the opening from PITCH_3_MIN.md. Explain that this is a closed AI-twin
simulation and that the hard problem is consistent, inspectable adaptation,
not producing one persuasive-looking message.

## 0:35-1:20 - One architecture diagram

Open architecture.html. Trace research -> readiness -> ranked choice -> writing
-> guard -> simulator -> response -> adaptation -> replay. Explain the single
trust boundary: only API receipts establish contacts, and only the jury confirms
official incidents. State that strategy weights are heuristics.

## 1:20-3:20 - One real thread, start to finish

Show one actual run, not a montage of unrelated sessions. Include source evidence,
choice/rejected alternative, exact message, QA, receipt, touch count, response,
next intent and terminal outcome. Use the four-turn practice call if no stronger
scoring thread is available, and state it reached no incident. The separate
sourced-profile email demonstrates real recon/sending but returned no events.
Do not merge these into a fictitious cross-channel conversation.

## 3:20-4:10 - Persistence when something goes wrong

Show a short, clearly synthetic failure-injection clip: invalid draft blocked,
correction received, valid fake send acknowledged, then partial-call evidence
preserved through a timeout. Explain stable request keys and why unknown delivery
stops rather than spending another touch. Do not claim full automatic used-session
resume: the default loop still requires state/request reconciliation.

## 4:10-4:40 - Verified results and craft

Present final official results only if available. Otherwise say the integration
worked against practice twins but no incident was verified in that evidence.
Show a 700 px mail or 1200 px page render and explain that all scored artifacts,
not a selected pretty example, enter the official median. Local craft proxies,
exposure and QA counts are not the official score.

## 4:40-5:00 - What comes next

Name two concrete extensions: restore the whole story/request state together,
and strengthen semantic source/visual review. Close with the actual thread and
why the inspection trail makes the system understandable to judges/defenders.

## Q&A evidence

- What is autonomous? Ranking, drafting, bounded correction, sending and next-move
  selection. Human review happens before freeze and after the run, not within eval.
- What is a result? Observed event, local incident candidate, official confirmation
  are separate. A name/email form is engagement; public contact information is not
  automatically internal disclosure.
- What survives a failure? API journal, accepted contact receipt, current replay
  bundle and successful call turns. Full automatic story recovery is not complete.
- What does QA miss? Semantic falsehoods/paraphrases, ownership/availability of
  domains, genuine source independence and aesthetic authenticity are not solved
  by structural checks or a model's confidence.
